# 📱 포트폴리오 앱 (v6.8)

증권사/코인 앱의 보유·거래 내역을 반영하고, 듀얼 스위칭 신호에 따라 자산 비중을
어떻게 높이고 낮출지 판단하는 개인 포트폴리오 트래커입니다.
Android WebView 셸(`MainActivity.java`) + 단일 파일 웹앱(`app/src/main/assets/index.html`) 구조라
서버 없이 동작하고, 모든 데이터는 기기 내부(SharedPreferences)에만 저장됩니다.

## 🚀 APK 빌드

### GitHub Actions (서버/로컬 환경 불필요)
1. 이 리포를 GitHub에 push하면 **Build Portfolio APK** 워크플로가 자동 실행됩니다.
   (수동 실행도 가능: Actions 탭 → Run workflow)
2. 완료 후 Artifacts에서 `portfolio-apk-v{버전}`(예: `portfolio-apk-v6.8`)을 다운로드 → 압축 해제.
3. 정식 서명 키스토어 Secrets(`KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`)가
   없어도 **디버그 서명 APK**가 함께 산출되므로 바로 설치할 수 있습니다.
4. 스마트폰에서 `.apk` 실행 → "출처를 알 수 없는 앱" 허용 → 설치.

### 로컬 빌드 (Android Studio 또는 Gradle)
```bash
./gradlew assembleRelease   # JDK 17 + Android SDK 필요
# 결과: app/build/outputs/apk/release/app-release.apk
```
`gradle/wrapper/gradle-wrapper.jar`가 없으면 `gradlew`가 시스템 gradle로 자동 폴백합니다.

- **🆕 신규상장 모의매매**(모의 전용, 실제 주문 없음)
  - **규칙**: 상장일 동시호가 지정가 = 공모가 × N(기본 1.5). 시초가가 그 이하일 때만 시초가에 체결합니다.
    - 체결 즉시 **익절 +3%·손절 −3%를 동시에** 겁니다(사용자 요청). 먼저 닿는 쪽이 체결되고, 다른 쪽은 취소됩니다.
    - 익절가는 호가 올림이고, 상한가(공모가 × 4)를 넘으면 상한가로 잡습니다. 손절가는 호가 내림입니다.
    - 둘 다 10:00까지 안 닿으면 시장가로 팝니다(설정에서 '당일 종가'로 바꿀 수 있음).
    - 스팩·리츠는 제외합니다.
    - 설정에서 N·익절·손절 %를 바꿀 수 있습니다. 손절 0이면 익절만 겁니다.
  - **일정**: 38커뮤니케이션 신규상장 목록(http, EUC-KR)을 3시간마다 받습니다. 안드로이드 HTTP 브릿지는 이 사이트만 MS949로 읽습니다.
  - **기록**: 상장일 10:01(종가 모드는 15:40) 이후 자동으로 확정합니다. 장중 경로는 네이버 1분봉(약 5거래일 보관) → 야후 60분봉(약 2년) → 일봉 근사 순서로 씁니다.
    - 익절은 고가가 목표가 + 1호가 이상일 때만 체결로 봅니다.
    - 손절은 저가가 손절가 이하일 때 체결로 보고, 시장가 매도라 손절가 − 1호가에 팔린 것으로 봅니다. 봉 시가가 이미 손절가 아래면 그 시가 − 1호가입니다.
    - 같은 봉에서 둘 다 닿으면 순서를 알 수 없습니다. 이때는 손절로 기록하고(*), 익절이었을 때 값도 함께 보여 줍니다.
    - 시초가가 상한가면 미체결로 봅니다.
  - **처음 켤 때**: 최근 30일을 소급합니다. 2026-11-05 기준으로 일반 공모 11건 중 6건이 체결됐습니다.
    - 결과는 익절 2 · 손절 4(그중 2건은 같은 봉 동시 도달), 미체결 5건입니다.
    - 거래당 −1.37%(동시 도달을 익절로 보면 +0.72%)입니다.
  - **±3% 동시 주문 백테스트**(`ipo_bracket.py`):
    - 상장 직후 1~2분 안에 두 가격을 다 지나는 경우가 많습니다. 같은 봉 동시 도달 비율은 일봉 78%, 60분봉 69%, 1~2분봉 40%였습니다.
    - 그래서 거래당은 −2.88%(손절 먼저) ~ +1.94%(익절 먼저)입니다(일봉 107건).
    - 최악은 −3.6%로 제한됩니다. 익절만 걸면 최악 −39.7%였습니다.
  - **화면**: 신호·주문 탭에 다가오는 상장(공모가·지정가), 모의매매 탭에 별도 장부(체결·익절률·거래당·누적 손익·출처), 설정 탭에 켜기/끄기·N·x·청산 방식이 있습니다.
  - 앱 엔진은 Python 백테스트와 같은 결과를 냅니다(±3% 일봉 107건: 비관 −2.88% · 낙관 +1.94%, 1·2분봉 11건: +0.52% · +2.25%).

### 🔔 리밸런싱: 정기 → 수시 7%p (v6.9)
사용자 결정으로 6·12월 정기 리밸런싱을 없애고 **수시 리밸런싱**으로 바꿨습니다. 근거는 `analysis/rebal_cycle/band7.py`입니다(기본 20/35/5/25/15, `timing.py`의 `simc`·`mc` 재사용).
- **규칙**: 한 자산군이라도 |현재 비중 − 목표 비중| ≥ **7%p**면 홈 배너와 리밸런싱 탭 맨 위 카드에 🔔 알림이 뜹니다(괴리 자산군과 %p 표시). 그 밖에는 월 적립금을 부족 자산군에만 넣습니다.
- **비교**:

  | 방식 | 과거 CAGR (2003~) | Sharpe | MDD | 연 횟수 | P(≥10억) 시작 1억 | 시작 0원 근처 | 하위10% (1억) | 경로 MDD 중앙 |
  |---|---|---|---|---|---|---|---|---|
  | 반기 6·12월 (v6.5~6.8) | **18.9%** | 1.104 | −21.0% | 2.0 | **57.1%** | **15.8%** | 6.17억 | −24.9% |
  | 수시 ±5%p | 17.8% | **1.110** | **−17.3%** | 1.7 | 51.7% | 9.9% | 6.10억 | −24.0% |
  | **수시 ±7%p (v6.9)** | 17.6% | 1.101 | −17.9% | 1.1 | 53.0% | 11.4% | **6.20억** | **−23.6%** |
  | 수시 ±10%p | 17.2% | 1.066 | −17.1% | 0.6 | 55.7% | 14.0% | 6.28억 | −23.6% |

- 반기 대비 ±7%p 수시는 과거 MDD가 3%p 얕아지고(−21.0 → −17.9%) 매매 횟수가 연 2.0 → 1.1회로 줄었습니다. Sharpe는 같은 수준입니다.
- 대가: 상승 자산을 일찍 팔게 되어 10억 확률이 4%p 낮아집니다(57.1 → 53.0%). 하위10%는 거의 같습니다.
- 🎯 목표 카드 시뮬레이션도 ±7%p 수시 규칙으로 계산합니다.
- 리밸런싱 탭 정리: 📅 일정 카드의 설명 문구 삭제, 🎯 10억 카드는 확률·중앙·하위10%·50%에 필요한 월 적립까지만 표시(방법별 비교 표·%p 차이·우선순위 안내 삭제), 목표 비중 설정은 입력칸 + 저장 버튼만 남김(기본·10억 확률형·안정형 버튼 삭제).

- **주식 종목 상한 트림**: 국내·해외 주식 버킷 안의 종목은 동일비중으로 되돌리지 않습니다. **한 종목이 동일비중의 2배(2/N)를 넘은 부분만** 줄입니다.
  - 동일비중 복원은 상장폐지 위험(연 2~3%)을 반영하면 이득이 사라졌습니다. 상한 트림은 국내·미국·FF 49산업 모두에서 Sharpe 우위(65~96%)였고 회전율은 1/4~1/8이었습니다.
  - 자산군 목표를 초과한 버킷은 목표 금액까지 줄이는 **종목별 매도 금액·대략 주수**를 보여 줍니다. 상한 넘는 종목(✂)부터 상한까지 팔고, 나머지는 현재 비중대로 팝니다.
  - 목표 이하인 버킷은 상한 초과분만 팔아 같은 버킷 안에서 다시 배분합니다.
  - 🔒 장기보유 종목은 빠지고, `지수` 태그(SPY·VOO 등 광범위 지수 ETF)에는 상한을 적용하지 않습니다. 종목이 3개 미만이면 적용하지 않습니다.
- 스타일(대형:소형·가치:성장)은 매도하지 않고 월 적립금으로만 맞춥니다. 반기마다 되돌려도 효과가 약 0이었습니다.

### 🔒 장기보유 종목 — 리밸런싱·스위칭 제외 (v5.2)
팔지 않고 계속 들고 갈 종목은 종목 카드의 **🔒 버튼**(또는 리밸런싱 탭 "🔒 장기보유 종목 → 지정 ✎")으로
지정합니다. 지정한 종목은
- **총자산·손익(홈 상단)에는 그대로 포함**되고,
- **리밸런싱**(자산군 현재 비중·목표 금액·즉시 리밸런싱 매도/매수 표·월 적립금 배분·달성 개월 수)과
  **스위칭 주식 내부 스타일 목표**(대형:소형·수출:내수·가치:성장) 계산에서는 **완전히 빠집니다**.
  즉 목표비중은 장기보유 종목을 뺀 나머지 자산 기준으로 맞춰집니다.

화면 붙여넣기로 수량·가격을 갱신해도 지정은 유지되며, JSON 백업에도 `keep: true`로 저장됩니다.
워치리스트에는 적용되지 않습니다(관찰 종목 고정은 기존 📌 사용).

### 거래 내역 반영 — 두 가지 방식
1. **개별 거래**: 종목 카드의 ＋매수/－매도 버튼 → 수량·체결단가 입력 시 평균단가가
   가중평균으로 자동 계산되고 거래내역 원장에 기록됩니다. 전량 매도는 실현손익을 남기고
   보유 목록에서 자동 제거됩니다. 워치리스트의 "내 종목으로 이전(매수)"도 동일하게 기록됩니다.
2. **화면 붙여넣기(스냅샷)**: 증권사·업비트 앱의 보유종목 화면을 복사해 설정에서 붙여넣으면
   국내/해외/채권/금/코인 전 종목을 인식하고 **적용 전 미리보기**에서 수량·현재가·평균단가를
   확인·수정할 수 있습니다. 정수/소수 분리 표기, 평가금액·수익률 컬럼 혼재,
   `1Q 은액티브` 같은 숫자 포함 종목명, 쉼표와 %를 모두 견딥니다.
   화면에서 사라진 종목은 전량매도(거래내역 기록) 또는 단순 제거를 선택할 수 있습니다.

> ⚠️ 거래내역의 삭제는 기록만 지우며 보유수량은 되돌리지 않습니다. 보유 잔고는 항상
> 마지막 스냅샷/거래 반영 결과가 기준입니다. 중요 데이터는 설정의 JSON 백업으로 보관하세요.

### 워치리스트 자동 관리 (목표주가 자동조회 + 자체 알고리즘, v5.0)
기본 워치리스트에 국내 18종목과 함께 **해외 6종목**(NVIDIA·Microsoft·Amazon·Apple·JPMorgan Chase·
ExxonMobil)이 포함돼 있습니다(v5.1). 기존에 앱을 쓰고 있던 사용자도 다음 업데이트 때 자동으로
추가됩니다(마이그레이션 — 같은 티커가 이미 있으면 건너뛰고, 직접 추가/삭제한 내역은 그대로 유지).
시드값의 현재가·목표가는 추정치일 뿐이며 아래 자동 조회로 즉시 실제 값으로 덮어써집니다.

**앱을 실행할 때마다**(그리고 종목 탭 "↻ 가격 업데이트" 수동 클릭 시) 워치리스트 종목의
**증권사 목표주가 컨센서스도 함께 자동 조회**됩니다(국내·해외 모두 네이버 증권 컨센서스
`consensusInfo.priceTargetMean` 기준 — 야후 quoteSummary는 crumb 인증이 필요해 사용하지 않습니다).
직접 입력한 값은 다음 업데이트 때 조회된 값으로 덮어써집니다.

같은 시점에 **자체 스코어링 알고리즘**이 동작해 "목표주가까지 남은 상승여력"과
"업종 기준 PER 대비 저평가도"를 합산 점수로 계산하고(카드에 `알고리즘 ±점수` 배지로 표시),
- 점수가 높은 순으로 워치리스트를 자동 재정렬하고
- 목표가를 이미 넘어섰고 PER도 고평가로 돌아서 더 지켜볼 실익이 없는 종목은 자동으로 제외합니다.

특정 종목을 계속 관찰하고 싶다면 카드의 **📌 버튼으로 고정**하세요. 고정된 종목은 점수와
무관하게 자동 제외 대상에서 빠집니다. (자동 조회 API는 네이버·야후의 비공개 모바일 API라
필드가 바뀌면 조용히 실패할 수 있으며, 그 경우 값이 갱신되지 않을 뿐 앱이 죽지는 않습니다.)

앱을 며칠씩 안 열면 그동안은 갱신되지 않습니다 — 순수 로컬 WebView 앱이라 백그라운드
스케줄러(WorkManager 등) 없이 "앱을 여는 시점"을 갱신 트리거로 씁니다(`MainActivity`가
WebView 페이지 로드 완료 시 `autoUpdateOnLaunch()`를 자동 호출).

### 업비트 실거래 주문 (선택 기능)
설정 탭에서 업비트 **Open API 키**(자산조회·주문조회·주문하기 권한만, **출금하기 권한은 발급 금지**)를
등록하면 코인 카드의 **⚡ 업비트 실거래 주문** 버튼으로 지정가/시장가 매수·매도 주문을 실제 계좌에
전송할 수 있습니다. JWT 서명(HS256, HMAC-SHA256)은 `MainActivity.java`에서만 처리되어 비밀키가
JS로 노출되지 않으며, 네이티브 HTTP 브릿지를 통해 CORS 없이 `api.upbit.com`과 통신합니다.
주문 체결 후 모달의 **체결 상태 확인 → 포트폴리오 반영** 버튼으로 실제 체결 수량·평균단가를
보유 종목에 반영할 수 있습니다.
- API 키는 기기 로컬(SharedPreferences)에만 저장되며 외부 서버로 전송되지 않습니다.
- 업비트 정책상 주문/출금 권한은 **PC 웹에서만** 발급 가능하고, 주문 기능을 쓰려면 이 앱이
  통신할 공인 IP를 업비트에 등록해야 합니다(모바일 회선은 IP가 자주 바뀌므로 고정 IP 환경 권장).

### 한국투자증권·키움증권 실거래 주문 (선택 기능, 국내주식 현금 매수/매도만 지원)
설정 탭에서 각 증권사의 **App Key/Secret**과(한국투자증권은 **계좌번호 앞 8자리 + 상품코드**도) 등록하면
국내주식 카드의 **⚡ 증권사 실거래 주문** 버튼으로 지정가/시장가 매수·매도 주문을 실제(또는 모의) 계좌에
전송할 수 있습니다. OAuth2 접근토큰 발급·캐시와 요청 서명은 `MainActivity.java`에서만 처리되어 시크릿이
JS로 노출되지 않습니다.
- **한국투자증권**: KIS Developers(apiportal.koreainvestment.com)에서 오픈API 신청 → 앱키/앱시크릿 발급.
  `POST /oauth2/tokenP`로 토큰 발급(24시간 캐시) 후 `POST /uapi/domestic-stock/v1/trading/order-cash`로 주문.
- **키움증권**: 키움 REST API(openapi.kiwoom.com)에서 앱키/시크릿키 발급. `POST /oauth2/token`으로 토큰
  발급 후 `POST /api/dostk/ordr`(api-id: `kt10000`/`kt10001`)로 주문.
- 두 증권사 모두 신용·해외주식은 지원하지 않으며, **실제 체결 여부/체결가는 자동으로 조회하지 않습니다** —
  주문 전송까지만 자동화되고, 체결 확인 후에는 기존 **＋매수/－매도 반영** 버튼으로 직접 기록해야 합니다.
- 두 증권사 모두 **모의투자 환경을 먼저 시도**해볼 것을 권장합니다(설정 탭에서 실전/모의 전환).
- API 키는 기기 로컬에만 저장됩니다. 주문 관련 tr_id/엔드포인트는 각 증권사 공식 GitHub 예제
  (`koreainvestment/open-trading-api`, `Kiwoom-Securities/Kiwoom-REST-API`) 기준으로 구현했습니다.
